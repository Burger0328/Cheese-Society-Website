The most repetitive part of this assignment was copying the same shared page structure into every HTML file. Each page needed the same header, navigation links, logo, and footer, but I still had to update relative paths depending on whether the file was in the project root or inside the `guide` folder. I also repeated the same stylesheet links and metadata structure across every page. The family pages were especially repetitive because they shared almost the same HTML structure, with only the title, image, content, and previous/next links changing.

The main issue when moving files into nested folders was that relative paths stopped working. For example, a path such as `styles/site.css` works from the root `index.html`, but from `guide/index.html` it must become `../styles/site.css`. The same issue happened with images and navigation links. At first, some pages loaded without styles or showed broken images because the browser was looking for those files inside the `guide` folder. This made it clear that file location directly affects every relative URL in the document.

A tool I would want is one that generates the shared page skeleton automatically. I would define the site header, navigation, footer, stylesheet links, and metadata template once, and the tool would insert them into each page with the correct relative paths. For the family pages, I would also want to store the cheese information as structured data and generate each detail page from one reusable template. This would reduce copy-and-paste mistakes, keep navigation consistent, and make future changes easier. Web components or a static site generator would solve many of the repetitive problems in this assignment.
